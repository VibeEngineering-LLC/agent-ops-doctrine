## Норма L1 — первоисточник (сверено напрямую 2026-08-30)

Дословно: «Size: target under 200 lines per CLAUDE.md file. Longer files consume more context and
reduce adherence» — `https://code.claude.com/docs/en/memory`, раздел «Write effective
instructions». ⚠ Прежняя атрибуция «best-practices» была неточной страницей — исправлено 30.08.

Оттуда же (`https://code.claude.com/docs/en/best-practices`): «Bloated CLAUDE.md files cause
Claude to **ignore your actual instructions**». Ограничение — про ИСПОЛНЯЕМОСТЬ, не про расход
контекста. Движок технически файл НЕ обрезает (лимит 4 MiB); 200 строк — рекомендация против
деградации адгеренса, не hard cutoff. Не путать с ДРУГИМ механизмом — `MEMORY.md` (auto memory),
у которого 200 строк / 25 КБ действительно технический hard-limit.

**Диагностический критерий оттуда же:** если я нарушаю собственное записанное правило — файл
слишком длинный, и правило в нём теряется. Прецедент дрейфа: четыре рецидива своих же свежих
правил за сутки (`надзорный:W-060/063/065/066`).

⚠ **Норма «≤3% окна» СНЯТА** (`надзорный:W-067`, 2026-08-30): она была введена собственной
арифметикой агента и мерила РАСХОД КОНТЕКСТА, тогда как ограничение первоисточника — про
АДГЕРЕНС. Числа строк в тексте самого правила намеренно не фиксируются — протухают быстрее
правки; смотреть `wc -l` на момент чтения.

## #LEAN-1 — приёмка сокращения (2026-08-30, из приёмки сжатия)

**«Вынес в reference» — способ потерять норму законно выглядящим образом.** Указатель на тело
засчитывается как сохранение требования ТОЛЬКО после открытия целевого файла и предъявления
места (`file:line`), где вынесенное реально лежит.

Приёмка сокращения делается **по списку требований**, выписанных из старой версии своими
словами. Сверка идентификаторов, путей и счётчиков вхождений — это ярус 0, она даёт ложное
«потерь нет» (`надзорный:W-062`).

Провенанс (дословные цитаты оператора), вынимаемый из машинного слоя, попадает в
`references/operator-verbatim.md` В ТОТ ЖЕ ХОД, иначе исчезает навсегда.

Счётчик вхождений НЕ диагностичен: «было 2, стало 1» бывает снятием дубля, а не потерей —
смотреть контекст каждого вхождения.

## Критерии прополки

- «Убери строку — приведёт ли это к ошибке? если нет, режь».
- «Если выделено многое, не выделено ничего».
- Операторские фиксации verbatim — в details; в CLAUDE.md однострочный императив + дата.
- История инцидентов → history-файл, НИКОГДА inline.
- Превышение лимита при очередной правке → lean-рефакторинг в тот же ход, не «потом».

## Дерево «куда писать что»

```
Новое знание/правило?
├─ Императив поведения (применяется каждый ход/сессию)
│    → строка таблицы в CLAUDE.md (проектный или глобальный) + тело в details/references
├─ Операторская фиксация («запомни навсегда», дословная цитата)
│    → цитата VERBATIM в details/references + в CLAUDE.md однострочный императив + дата
├─ Процедура / код-блок / чеклист / worked example
│    → references/*.md скилла или проекта; в CLAUDE.md/SKILL.md — указатель «читать при X»
├─ Домен-знание (протокол, карта, реестр устройств, quirks, нормативы)
│    → скилл контура (SKILL.md ядро или его references/), НЕ CLAUDE.md
├─ Тест-план (§17)
│    → SKILL.md секция «Тест-планы»: заголовок+шаги, длинные → references/test-plans.md
├─ История инцидента / решённая проблема / хронология
│    → history-файл (audit/*-history-*.md), НИКОГДА inline в CLAUDE.md/SKILL.md
└─ Разовое/ситуативное (не пригодится повторно)
     → не фиксировать вообще (карв-аут §10)
```

## Правила для новых скиллов (при создании, не задним числом)

1. SKILL.md с первого дня: ядро ≤~4000 tok (роль, hard rules, матрица выбора, ключевые файлы,
   тест-планы-указатели) + `references/` для тел. Метрика — токены, НЕ строки (tok/line ×3.5 по типу:
   проза ~14-16, плотные таблицы/hex ~30-47 — ~200 строк прозы ЛИБО ~90 плотных; мерить
   `надзорный\scripts\bench_skill_context.py`). Не «сначала монолит, потом разберём».
2. description скилла = триггеры вызова, грузится ВСЕГДА у всех (always-on налог; 50 описаний ≈
   8014 tok/сессию по REF-2) — бюджет градуированно: ≤80 tok однозначный триггер, ≤150 tok с разграничением от соседа, ≤250 tok диспетчерский (значение ядра §28; сведено DOC-1 шаг 2); превышение верхней планки — резать. «В ноль» резать нельзя (нужно для
   авто-роутинга) — богатство уносить в первый экран тела, не во frontmatter.
3. Один скилл = одна зона. Толстеет от второй темы → выделить подскилл с узким description
   (паттерн design-семейства), не растить монолит.
4. Код-блоки >15 строк в SKILL.md → файл в `scripts/` + указатель (§15/§16).
5. Секция «Ключевые файлы» (§17) при разрастании — reference-таблица в `references/key-files.md`
   + одна строка-указатель в ядре; §17 это допускает (файлы «доступны», не «inline»).
6. Safety-ядро (запреты необратимого, гейты, скраб, HARD RULE с эмпирикой краша) — inline
   всегда, в references не выносить.

## Анти-паттерны (это и раздуло слой до 2330 строк)

- Секция с заголовком + обоснованием + историей + карв-аутами inline в CLAUDE.md — вместо
  однострочного императива.
- Дубль глобального правила в проектном CLAUDE.md «для надёжности» — глобальный и так грузится.
- Дубль содержимого скилла в CLAUDE.md (шаблоны, карты) — скилл грузится при вызове, этого достаточно.
- «Запишу подробно сейчас, ужмём потом» — потом не наступает; писать сразу по дереву.
- История инцидента как аргумент правила inline — аргумент живёт в history, правило — одной строкой.

## Дисциплина поддержания

- Любая правка CLAUDE.md/SKILL.md: перед сохранением глянуть счётчик строк; лимит превышен →
  ужать в этой же правке.
- Периодический чек (при годовом/квартальном аудите контура): `wc -l` по CLAUDE.md и SKILL.md
  зоны; превышения → lean-рефакторинг по METHOD.md.

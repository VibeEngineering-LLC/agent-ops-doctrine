# §25 Не переключаться + нумерация замечаний + учёт — тело (вынесено из CLAUDE.md §25, 2026-07-11 lean)

> **Примечание к публичной копии.** Файл выгружен из приватной рабочей конфигурации: имена контуров заменены ролями, личные пути — плейсхолдерами. Ссылки на файлы, отсутствующие в этом репозитории (реестры скиллов и инструментов, журналы инцидентов, история), указывают на приватные части конфигурации и намеренно не публикуются.

Императив-суть — в `~/.claude/CLAUDE.md` §25. Применяется ко ВСЕМ сессиям/контурам/агентам.

**Зафиксировано оператором 2026-06-27 дословно:** «не переключайся, присваивай
замечаниям номера, веди учёт замечаний. запомни навсегда».

**ИМПЕРАТИВ:** когда оператор присылает новое замечание/правку посреди уже идущей работы:

1. **НЕ переключаться** с текущего активного замечания на новое, даже если новое кажется
   проще/быстрее/важнее. Доделать текущее → потом следующее по очереди. Исключение —
   только явная команда оператора «брось это, делай вот это» (тогда текущее → в backlog,
   не «забыто», а в учёт с пометкой «прервано на …»).
2. **Каждому замечанию — свой номер** в стабильной нумерации сессии. Формат — `#<префикс>-N`
   (например `#UI-1`, `#UI-2`, `#FW-1`, `#DOC-3`); префикс — зона/контекст, N — порядковый
   в этой зоне в этой сессии. Номер присваивается СРАЗУ при поступлении, до начала работы.
3. **Учёт замечаний** — через `TaskCreate` (встроенная система задач):
   - subject начинается с номера: `#UI-1: вернуть «срез спектра» под водопадом`;
   - один TaskCreate = одно замечание, не объединять разные замечания в одну задачу;
   - текущее → `in_progress`, поступившие новые → `pending`, выполненные → `completed`;
   - при докладе оператору всегда называть номер (`#UI-2 готов, перехожу к #UI-1` —
     если потребовалось перебить порядок по явной команде).
4. **При новом замечании посреди работы** ответ оператору всегда:
   (а) подтвердить регистрацию: «принял как #UI-N, добавил в очередь»;
   (б) явно сказать что продолжаю текущее (`сейчас доделываю #UI-K, потом #UI-N`),
       либо явно спросить разрешения на переключение, если новое явно срочнее;
   (в) НЕ хвататься за новое молча.

**Anti-pattern (что было до фиксации правила, 2026-06-27 сессия контура прошивок):** оператор присылает
замечание «не отображается срез спектра / нужен i18n / нужны линии нуклидов» → ассистент
начинает читать код водопада; оператор присылает следующее замечание «при переключении
вкладок сбрасываются настройки» → ассистент бросает первое и хватается за второе. Так
**нельзя** — оператор не видит общей картины замечаний, а ассистент теряет нить первого.

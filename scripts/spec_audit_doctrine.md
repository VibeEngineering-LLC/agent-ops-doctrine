# Спека: `audit_doctrine.py` — стерильный многолинзовый аудит текстового документа доктрины

Сгенерируй ОДИН самодостаточный Python-файл. Выведи ТОЛЬКО код, без пояснений до или после.

## Назначение

Скрипт проводит стерильный аудит markdown-документа (доктрины/методики) силами локальной
модели Ollama: несколько независимых проходов РАЗНЫМИ линзами, каждый — в чистом контексте,
без результатов других проходов. Собирает находки в JSON.

## CLI

```
python audit_doctrine.py --doc <путь.md> --out <путь.json> [--model qwen3-coder:30b]
                         [--lenses all|contradictions,executability,...] [--selftest]
```

- `--doc` — обязателен (кроме `--selftest`), путь к markdown-файлу.
- `--out` — обязателен (кроме `--selftest`), куда писать JSON результата.
- `--model` — по умолчанию `qwen3-coder:30b`.
- `--lenses` — список линз через запятую или `all` (по умолчанию `all`).
- `--selftest` — прогнать самопроверку (см. ниже) и выйти; Ollama НЕ вызывать.

## Механическая часть (без модели) — функция `structural_checks(text)`

Возвращает список находок-словарей. Проверки:

1. **Битые перекрёстные ссылки на разделы.** Собрать множество существующих номеров разделов
   из заголовков вида `^## (\S+?)\.` (например `1.`, `3а.`, `6б.`). Затем найти все упоминания
   вида `§<номер>` и `§§<номер>` в тексте. Если упомянут номер, которого нет среди заголовков
   ЭТОГО документа И он не начинается с цифры, относящейся к внешней доктрине (см. ниже) —
   находка типа `broken_ref`.
   ВАЖНО: ссылки на внешнюю доктрину (номера разделов родительского документа, не этого файла)
   считать допустимыми. Список внешних номеров задать константой `EXTERNAL_SECTIONS`,
   настраиваемой под конкретный аудируемый документ (пример значений в комментарии рядом с
   константой, не зашивать в логику).
2. **Упоминание файлов, которых нет на диске.** Найти пути вида `` `...md` `` и абсолютные
   `C:\...`/`D:\...`. Для абсолютных — `os.path.exists`; несуществующий → находка `missing_file`.
   Относительные имена (`loop-engineering-source.md`) проверять в каталоге самого документа.
3. **Пустой раздел** — заголовок, за которым до следующего заголовка меньше 2 непустых строк →
   `empty_section`.
4. **Обещание без адреса** — строки, содержащие «см. ниже», «см. выше», «описано в», но не
   содержащие ни `§`, ни имени файла → `dangling_pointer`.

Каждая находка: `{"kind": "<тип>", "line": <номер строки, 1-based>, "quote": "<строка, обрезать до 200 симв>", "detail": "<пояснение>"}`.

## Линзы (проходы модели) — константа `LENSES`

Словарь `имя -> (заголовок, инструкция)`. Ровно пять линз, инструкции формулируй так, чтобы
проход НЕ знал, что ищут другие проходы, и НЕ получал никаких ожидаемых ответов:

1. `contradictions` — «Найди внутренние противоречия: места, где документ требует одного в одном
   разделе и несовместимого с этим в другом. Только противоречия внутри текста, не сверяй с
   внешними источниками.»
2. `executability` — «Ты инженер, которому поручено построить описанное строго по этому
   документу, без права задавать вопросы автору. Перечисли конкретные места, где инструкции
   недостаточно для исполнения: что именно не определено, какое решение придётся выдумать.»
3. `ambiguity` — «Найди формулировки, допускающие два и более несовместимых прочтения
   исполнителями. Для каждой приведи оба прочтения.»
4. `unenforceable` — «Найди требования, соблюдение которых нельзя проверить: нет механизма,
   критерия или ответственного. Правило, которое некому и нечем проверить, считается находкой.»
5. `loopholes` — «Ты недобросовестный исполнитель, желающий формально соблюсти документ, но
   сделать по-своему. Опиши конкретные лазейки: что можно сделать, не нарушив букву текста, но
   нарушив очевидное намерение.»

## Промпт прохода — функция `build_prompt(doc_text, lens_name, lens_title, lens_instruction)`

Структура промпта (строго; НЕ включать в него никаких выводов, гипотез или ожидаемых ответов):

```
Ты проводишь независимую экспертизу документа. Ты не видел ничьих других замечаний
и не должен ни с кем соглашаться.

ЗАДАЧА: <lens_instruction>

КРИТЕРИЙ ПРИЁМКИ: каждая находка обязана указывать конкретное место в документе
(номер раздела или дословную цитату). Находка без привязки к тексту недопустима.
Если по твоей задаче находок нет — верни пустой список, это нормальный результат.

Верни СТРОГО JSON вида:
{"findings":[{"section":"<номер или заголовок раздела>","quote":"<дословная цитата до 200 символов>","problem":"<в чём проблема>","suggestion":"<что конкретно изменить>","severity":"high|medium|low"}]}

ДОКУМЕНТ:
<doc_text>
```

## Вызов модели — функция `run_lens(model, doc_text, lens_name, ...)`

- `guarded_generate(model=model, prompt=prompt, fmt="json", temperature=0.0, num_ctx=65536, want_gpu=True, priority=50, max_wait_s=900, extra_options={"num_predict": 8000}, project=os.environ.get("AUDIT_PROJECT_LABEL", "audit_doctrine"), agent="audit_doctrine")`
- Ответ: если dict — брать `resp.get("response","")`; иначе `str(resp)`.
- Парсить JSON. При `JSONDecodeError` — попытаться вырезать подстроку от первой `{` до последней
  `}` и распарсить ещё раз. Если снова не вышло — вернуть находку-заглушку
  `{"kind":"lens_failed","lens":<имя>,"detail":<первые 300 символов ответа>}` и НЕ падать.
- **Стерильность обязательна:** каждый вызов независим; НИКОГДА не передавать в промпт
  результаты других линз или предыдущих прогонов. В коде не должно быть накопления истории
  между вызовами.
- Замерять wall-clock каждого прохода.

## Главный поток

1. Прочитать документ, посчитать `sha256` первых 8 символов hex — для провенанса.
2. Выполнить `structural_checks`.
3. Прогнать выбранные линзы ПОСЛЕДОВАТЕЛЬНО (не параллельно — общий GPU).
4. Собрать результат:

```json
{"doc": "<путь>", "sha8": "<...>", "lines": <кол-во строк>, "model": "<модель>",
 "generated_at": "<ISO-8601 локальное время>",
 "structural": [...], "lenses": {"<имя>": {"seconds": <float>, "findings": [...]}},
 "totals": {"structural": N, "model": M, "failed_lenses": K}}
```

5. Записать в `--out`, напечатать в stderr краткую сводку: по каждой линзе количество находок и
   секунды, отдельной строкой — суммарно.
6. **Блок «ТРЕБУЕТ ТОЛКОВАНИЯ»** (обязателен, печатать в stderr после сводки): автоматически
   поднимать вопросы при аномалиях — линза вернула 0 находок; линза упала; все линзы вернули
   одинаковое количество находок; проход занял менее 5 секунд (подозрительно быстро для объёма);
   суммарно 0 находок модели при непустом документе. Если аномалий нет — печатать
   `ТРЕБУЕТ ТОЛКОВАНИЯ: пусто`.

## Самопроверка `--selftest` (Ollama НЕ вызывать)

Собрать в памяти синтетический markdown-текст, содержащий заведомо: одну битую ссылку на
несуществующий раздел (`§99`), один несуществующий абсолютный путь, один пустой раздел, один
«см. ниже» без адреса. Прогнать `structural_checks` и проверить, что найдены ВСЕ четыре класса.
Дополнительно прогнать на тексте БЕЗ дефектов и убедиться, что находок ноль.
Печатать `SELFTEST OK` и `sys.exit(0)`, либо `SELFTEST FAILED: <что именно>` и `sys.exit(1)`.
Самопроверка обязана уметь краснеть: она сравнивает найденные `kind` с ожидаемым множеством.

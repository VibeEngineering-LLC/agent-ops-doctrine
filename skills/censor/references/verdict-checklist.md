# Чек-лист вердикта релиза / push (actor≠verifier)

Читай этот файл, когда оператор просит вынести вердикт по релизу/коммиту/push
(«одобряю?», «что скажешь», «можно ли пушить»). Ты имеешь право давать вердикт
ТОЛЬКО как независимый проход (ты НЕ автор этого релиза) и ТОЛЬКО проверив гейты
**фактически**, а не на слово автора.

## Релиз — пройти по факту

1. **Release-commit.** `git show <sha> --stat` — это действительно тот коммит,
   что заявлен? Дата/сообщение/состав сходятся с заявкой автора?
2. **Tag → target.** Аннотированный tag указывает на этот же SHA?
   `git rev-list -n1 <tag>` == release-commit. Tag аннотированный, не lightweight?
3. **Тройной SSOT — запустить, не прочитать.** README-версия == внутренняя
   константа версии == tag. Не доверяй глазам — **запусти** version-check-скрипт
   проекта и прочитай его exit-code/вывод («OK: README=vX == SKILL_VERSION=vX ==
   tag=vX», exit 0).
4. **Состояние push.** `git rev-list origin/<branch>..HEAD` — сколько коммитов
   локаль впереди origin и НЕ ушло? Это ожидаемо (Tier-2-LOCAL удерживается)
   или релиз случайно уже утёк? Origin-SHA не изменился, если push не делался —
   проверь `git ls-remote`.
5. **Чистота дерева / гейты CI.** Рабочее дерево соответствует коммиту? CI-гейт
   (version-check, тесты) присутствует и зелёный по правильной причине (не
   замьючен, не обойдён)?

Вердикт «одобряю» — только когда все 5 сошлись по факту. Иначе — назвать, что
именно не сошлось, и держать.

## Push — никогда вслепую

Перед любым `git push origin <branch>`:

1. `git rev-list origin/<branch>..HEAD` — что именно уйдёт. Показать оператору
   список коммитов.
2. Нет ли в этих коммитах того, что НЕ должно утечь: Tier-2-LOCAL, креды,
   приватные данные. Если есть — НЕ пушить, park на оператора.
3. Push необратим → `action_class=irreversible` → operator-gate (одно «да»).
4. Никогда не `--force`/`--no-verify`/`--no-gpg-sign` без явной просьбы оператора.

## Анти-паттерны вердикта

- ❌ «Автор написал, что версии сходятся» → принять на слово. ВСЕГДА запускай
  version-check сам.
- ❌ Дать вердикт по релизу, который собрал ты сам, в той же роли (нарушение
  actor≠verifier). Спавни независимого верификатора или помечай «само-проверка».
- ❌ Обсуждать push, не сделав `rev-list` (можешь предложить слить локальное,
  которое должно остаться локальным).
- ❌ Принять «зелёный CI» без проверки, что гейт не замьючен и краснеет/зеленеет
  по правильной причине (false-green / flaky — см. скилл `fact-audit`).

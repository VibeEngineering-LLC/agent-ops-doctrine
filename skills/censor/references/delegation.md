# Делегирование — pre-flight, шаблон, границы

Читай этот файл, когда нужно решить «отдать на Ollama / субагента или делать
самому» и как именно вызвать Ollama. Полная политика — в `~/.claude/CLAUDE.md`
(Local-First). Здесь — операционная выжимка для роли Цензора.

## Pre-flight перед КАЖДЫМ Agent()/Workflow/большим Read

Четыре вопроса. Если хотя бы один → ДА — сначала Ollama, потом (если надо) Claude:

1. **Извлечение по шаблону?** (поля из лога/PDF/CSV/dump, TSCF, метрики) →
   `qwen3-coder:30b`, `format='json'`.
2. **Шаблонная генерация?** (pytest-функции по списку, boilerplate, release-notes
   по образцу) → `qwen3-coder:30b`.
3. **Грубая классификация/фильтрация?** (валидность записей, дедуп по эвристике,
   tier-документы) → `qwen3-coder:30b`, `format='json'`.
4. **Длинная суммаризация >5000 строк / >100 КБ?** → `qwen3-coder:30b`, на выход
   markdown ≤200 строк.

Все четыре → НЕТ → задача для Claude/субагента (синтез, архитектура, адъюдикация).

## Жёсткие правила

- **НЕ читать большие файлы прямо в контекст Claude.** >5000 строк / >100 КБ —
  всегда сначала через Ollama-скрипт; Claude получает выжимку (JSON / markdown ≤200).
- **Массовые операции — всегда Ollama.** Claude получает только агрегаты.
- **Все `Agent()` — `run_in_background: true`** (если оператор не сказал
  «синхронно»). Последовательные фазы — тоже background: жди `<task-notification>`
  о фазе N, потом запускай N+1.
- **Бриф субагента обязан** содержать инструкцию использовать Ollama на шаблонной
  части. Claude-токены субагента — только на синтез/решения/git/анти-галлюцинацию.
- **Модель одна — `qwen3-coder:30b`** (generative) + `bge-m3` (эмбеддинги).
  Никаких fallback-цепочек моделей (fallback = источник нестабильности).

## Шаблон вызова (через three-tier guard, НЕ сырой requests)

Предпочтительно — `guarded_generate` (GPU→queue→CPU→Claude), он защищает от OOM
на общей машине (инцидент RTX 4090 24 ГБ, 2026-06-04):

```python
from _vram_guard import guarded_generate
response = guarded_generate(
    model='qwen3-coder:30b',
    prompt='...',
    want_gpu=True,
    priority=50,        # orchestrator=100, subagent=50, batch=10
    max_wait_s=600,
    options={'temperature': 0, 'num_ctx': 32768, 'format': 'json'},
)
```

Эталон guard'а: `C:\Users\<you>\.claude\skills\workflow\scripts\vram_guard_reference.py`.
**Подключается ИМПОРТОМ, не копией** (§33; практика копирования отменена миграцией
2026-08-28/29 — 17 путей с копиями сведены к импорту, расхождения версий были прямым
следствием копий):
```python
sys.path.insert(0, r"C:\Users\<you>\.claude\skills\workflow\scripts")
from vram_guard_reference import guarded_generate
```
Копия в проекте (`scripts/ollama/_vram_guard.py` и любая другая) — дефект, а не вариант.

## Context-инъекция (прежде чем сказать «Ollama не знает X»)

Если модель не знает свежий факт (API, alias, версии, внутренняя таксономия) —
это не приговор делегированию, а **отсутствующий context-файл**. Большинство таких
фактов публично документированы, стабильны на месяцы, компактны (≤5 КБ). Положи
их в `<project>/.../_context/<domain>_<date>.md`, helper подставит под заголовок
`═══ КОНТЕКСТ: <domain> ═══`. One-time создание дешевле, чем эскалация на Claude
на каждый вопрос.

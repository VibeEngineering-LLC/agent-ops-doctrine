- **16 ловушек** измерительного стенда, каждая воспроизведена на работающем стенде и проверена
  в обе стороны: от эталона, который пересчитывается вместо сравнения, до ранжирования без

  4→1→2→3→2→0) — смена ВИДА проверки даёт больше, чем смена проверяющего.

  токенизация кириллицы, self-preference bias судей, paired bootstrap, NIAH с вариацией глубины.

## Специфика Ollama, которую нельзя забыть

| Что | Почему важно |
|---|---|
| `num_ctx` задавать ЯВНО в каждом запросе | дефолт 4096; превышение молча обрезается, причём отбрасывается ГОЛОВА (инструкция), а ответ приходит с HTTP 200 без признаков обрезки |
| Только native `/api/generate`, не `/v1/chat/completions` | OpenAI-совместимый endpoint игнорирует `num_ctx` |
| `format='json'` — только для короткого атомарного ответа | на задачах, требующих рассуждения ДО ответа, роняет качество; на длинных перечислениях обрывает вывод |
| `think` — по ЗАДАЧЕ, не по модели | при `format=json` финальный JSON у части моделей уходит в поле `thinking`, а `response` пустеет |
| Выгружать модели перед серией (`keep_alive=0`), проверять `api/ps` | иначе занятая VRAM выглядит как провал модели |
| Один процесс на файл результата | два параллельных прогона пишут в один файл и дерутся за GPU |
| Спросить оператора перед прогоном | он работает на той же карте; выгрузка модели вырывает её у него из-под рук |

## Рабочие инструменты (контур Codeaudit)

`scripts/ollama/` репозитория `Verter73/Codeaudit`: `hard_bench_text.py` (стенд, 10 задач,
защита от всех 16 ловушек), `audit_checkers.py` (стерильный аудит чекеров), `oracle_check.py`
(поверка эталоном), `exp_fmt_vs_think.py` (решающий эксперимент с одной переменной),
`spec_bench_v2_methodology.md` (методика следующего прогона).

- **19 ловушек** измерительного стенда, каждая воспроизведена на работающем стенде и проверена

  токенизация кириллицы, self-preference bias судей, paired bootstrap, NIAH с вариацией глубины.

## Специфика Ollama, которую нельзя забыть

| Что | Почему важно |
|---|---|
| `num_ctx` задавать ЯВНО в каждом запросе | дефолт 4096; превышение молча обрезается, причём отбрасывается ГОЛОВА (инструкция), а ответ приходит с HTTP 200 без признаков обрезки |
| Только native `/api/generate`, не `/v1/chat/completions` | OpenAI-совместимый endpoint игнорирует `num_ctx` |
| `format='json'` — только для короткого атомарного ответа | на задачах, требующих рассуждения ДО ответа, роняет качество; на длинных перечислениях обрывает вывод |
| `think` — по ЗАДАЧЕ, не по модели | при `format=json` финальный JSON у части моделей уходит в поле `thinking`, а `response` пустеет |
| Выгружать модели перед серией (`keep_alive=0`), проверять `api/ps` | иначе занятая VRAM выглядит как провал модели |
| Один процесс на файл результата | два параллельных прогона пишут в один файл и дерутся за GPU |
| Спросить оператора перед прогоном | он работает на той же карте; выгрузка модели вырывает её у него из-под рук |
| Задание генерируется зерном (`BENCH_SEED`) — не все задания зависят от него в равной мере | у нас зерном управляются 4 из 10 заданий; остальные фиксированы и во всех прогонах дают тот же балл — новый экземпляр набора не растит выборку по ним |
| Отказ модели (зацикливание > N символов без завершения, таймаут запроса) — балл 0, остаётся в сравнении; обрыв сервера — выбрасывается | смешение даёт ложное занижение частоты отказов модели (см. ядро скилла, «Протокол прогона») |
| Общий рейтинг по разнородному набору задач — проверять на знакопеременность разницы между моделями, прежде чем публиковать | найдено: разница пары моделей меняла знак от задачи к задаче (+0,29 на одной, −0,50 на другой) — усреднение по набору не измеряло ничего |

## Рабочие инструменты (контур Codeaudit)

`scripts/ollama/` репозитория `Verter73/Codeaudit`: `hard_bench_text.py` (стенд, 10 задач,
защита от всех 19 ловушек; зерно набора — `BENCH_SEED`), `bench_compare.py` (сравнение раундов:
парный bootstrap, три исхода вердикта, балл по классам задач, стоимость правильного ответа —
`--selftest` мутационно проверен), `bench_reclass.py` (реклассификация отказов модели vs сбоя
среды + дедупликация псевдорепликации — тоже с `--selftest`), `audit_checkers.py` (стерильный
аудит чекеров), `oracle_check.py` (поверка эталоном), `exp_fmt_vs_think.py` (решающий
эксперимент с одной переменной), `spec_bench_v2_methodology.md` (методика прогона, актуализирована
по итогам первого запуска), `prompts/loop-bench-v2.md` (готовый промпт петли сравнения «под
ключ» с разбором каждого решения).

## 0. Вызов

```
Agent(description="<3–5 слов>", subagent_type="<тип>", model="<haiku|sonnet|opus|fable>",
      run_in_background=true, prompt=<бриф ниже>)
```
`model` — по § B.2c, кратко: **haiku** — весь список признаков для разметки уже дан в самом брифе (grep/перечень
во входе, применить механически); **sonnet** — критерий по ходу (дефолт): бриф просит прочитать код/логику и
самому решить, что считать дефектом/ответом; **opus** — проектирование нового или один из двух проходов перед
необратимым, либо провал sonnet; **fable** — только по запросу оператора или после провала opus. Граница
haiku/sonnet — судится по формулировке ЗАДАЧИ в брифе (если для её выполнения нужно ЧИТАТЬ и ПОНИМАТЬ код, а не
только сверять со списком — sonnet), не универсальная, спорные случаи — sonnet по умолчанию. В докладе строка
«ступень 3x: причина». Фон — всегда (§7).
`subagent_type` — из списка типов в системном напоминании ТЕКУЩЕЙ сессии (список меняется, в шаблоне не
зашивается умышленно — проверить перед составлением брифа); дефолт `general-purpose`, поиск только на чтение —
`Explore`, план в файл — `architect`.

## А. Бриф ИСПОЛНИТЕЛЮ

Субагент не видит разговора. Всё, что ему нужно, — в брифе; «как обсуждали», «продолжи» запрещены (PM № 7, 8, 28).

```
## Задача
<ОДНА операция, одной фразой, точный глагол: «добавь», «найди все», «перенеси», не «разберись/помоги».
Две операции — два брифа (PM № 1, 2, 6). Операция = действие над миром (найти, изменить, запустить);
форма результата («составь список», «оформи таблицей») — не вторая операция. «Найди и исправь» — две.
Зачем — одна строка, ЕСЛИ без неё исполнитель законно выбрал бы другой файл/метод/приоритет; чисто
информационная причина (не влияющая на выбор) — не писать.>

## Исходное состояние
<Что есть сейчас: абсолютные пути, sha/номер строки, что уже работает.
Что уже пробовали и почему не вышло — «не предлагай X, потому что Y» (PM № 13, 31). Не пробовали — так и
написать «не пробовалось», поле не опускать.>

## Целевое состояние
<Что должно существовать по окончании — бинарно: файл такой-то с тем-то; команда такая-то даёт rc=0 и число N
(PM № 3, 32).>

## Границы
- Работать только в: <пути>
- Не трогать: <пути; всегда — чужие зоны §12, .env/ключи, settings.json, хуки>
- Запрещено без возврата ко мне: push, удаление, перезапись незаменимого, установка пакетов, сеть на запись
  (PM № 4, 20, 23, 34)
- Блок гейта или хука (сообщение `hook error`, `PUSH GUARD`, `IRON MODE`, `WRITE GUARD` и т.п.) НЕ обходить — ни
  склейкой строк, ни другим инструментом (PowerShell, MCP, `python -`, inline-код), ни переименованием; вернуть
  отчёт с дословным текстом блока (эксперимент 24.09: обход склейкой у проверяющего; подобный случай в другом контуре)

## Когда остановиться и вернуть отчёт, НЕ продолжая
Фоновый субагент не может спросить оператора — он возвращает отчёт с вопросом (адаптация PM № 22, 35):
- действие необратимо или вне границ;
- есть два пути и выбор влияет на архитектуру/доктрину;
- одна и та же ошибка не устранена за 2 попытки (#DBG-1, PM шаблон H);
- нужный файл/инструмент не существует (не изобретать — §33).

## Критерий приёмки
- [ ] <бинарная проверка + команда, которой она доказывается>
- [ ] <…>

## Формат отчёта
1. Итог — одной строкой.
2. Что сделано — список; у каждого пункта доказательство: команда и её вывод / `file:line` / sha / число.
3. Допущения, на которых держится итог.
4. Что НЕ проверено и почему.
Ход рассуждений не нужен — только выводы и доказательства (PM № 26, 27, шаблон E).

## LESSONS
0–3 пункта «ожидал X → оказалось Y → обход Z» (гейт `lessons_gate.py` для брифов >600 симв.).
```

## Б. Бриф СТЕРИЛЬНОМУ ПРОВЕРЯЮЩЕМУ (#SA-7)

Отличается от А не формой, а тем, чего в нём НЕТ. Советы prompt-master «дай контекст прошлых попыток» и
«Memory Block» здесь ВРЕДНЫ: проверяющий, узнавший мои выводы, подтверждает их (§31.A, A.9).

```
## Задача
<Вычисли/найди независимо: «в файле X расчёт K — получи K по данным Y», «найди в артефакте Z всё, что не
доказано командой». Материал подаётся как чужой — без «мой», «я сделал».
Если проверяется конкретное утверждение — оно формулируется СИММЕТРИЧНЫМ вопросом, оба исхода равноправны:
«пропускает ли гейт X без Y — или проверка применяется?», а не «проверь, что гейт пропускает X».>

## Метод и граница
<Чем проверять: число — пересчёт скриптом; цитата/наличие — grep по источнику целиком; логика кода — чтение
файла целиком + прогон на построенном входе (не только grep: ветвления меняют смысл соседних строк);
поведение — прогон ТЕМ рантаймом, которым пользуется реальный потребитель кода (путь, который пишет инструмент Write, —
записью через Write, а не Python `open()`; URL git — самим `git`; хук — подачей JSON в процесс хука); прогон в другой
среде опровержением не считается. Граница — какие файлы/разделы; у второго
прохода граница ДРУГАЯ (#SA-8). Для числа — требование назвать раздел/строку источника.
Писать — только в свой scratchpad-каталог. Блок гейта или хука НЕ обходить (склейка строк, другой инструмент,
inline-код) — вернуть отчёт с дословным текстом блока.>

## Критерий приёмки
<Что считается «доказано»: вывод команды, `file:line`, совпадение числа до единицы последнего разряда.>

## Формат отчёта
Для каждого утверждения: доказано / не доказано / опровергнуто + доказательство.
Раздел `## LESSONS` — предпоследним. Самая последняя строка ВСЕГО ОТВЕТА субагента (после LESSONS, ничего за ней) —
ровно: «непроверенных утверждений: N, обходов с кодом 0: M» (#SA-11). Это требование к ОТВЕТУ субагента, не к тексту
брифа — в самом брифе порядок разделов «Формат отчёта» → «LESSONS» роли не играет.

## LESSONS
0–3 пункта.
```

**Не вписывать в бриф Б:** мои выводы и числа; ожидаемый результат; «правильно ли…», «проверь, что…
работает»; историю моих попыток; блок памяти сессии.

## В. Проверка брифа перед отправкой (механически, grep по тексту брифа)

| Искать | Для | Должно быть |
|---|---|---|
| `правильно ли`, `ожидается`, `должно получиться`, `у меня вышло` | Б | 0 совпадений (#SA-7, артефакт #SA-9) |
| `как обсуждали`, `продолжи`, `то, что`, `сделай всё` | А, Б | 0 (PM № 6, 7, 8) |
| `## Критерий приёмки` | А, Б | есть |
| `## LESSONS` | А, Б | есть |
| абсолютный путь — команда `grep -En "[A-Za-z]:[\/]"` по файлу брифа | А, Б | ≥1 совпадение |
| параметр `model=` в вызове | вызов | есть (#LOC-4, гейт `agent_model_gate.py`) |
| `НЕ обходить` (запрет обхода блока гейта) | А, Б | есть |
| `рантайм` (проверка в среде потребителя) | Б | есть |

**Замер 2026-09-24** (приватный журнал приёмки, 16 прогонов `sonnet`): шаблон Б против
реального брифа контура — обнаружение известных дефектов 2/6 против 2/6 (не различено), стоимость равна. Три строки
выше внесены по дефектам, найденным тем же экспериментом; их эффект НЕ замерен. Повторная стерильная проверка
исполнимости (`sonnet`, приватный отчёт проверки) нашла и закрыла 2 дефекта текста
(нерабочая grep-форма пути; путаница «порядок в брифе» / «порядок в ответе» для LESSONS/итоговой строки) и 3
неоднозначности (по указанию оператора «разбирай», текстом, без нового стерильного прохода — все три оценочные
формулировки, не новые проверяемые предикаты раздела «В»): источник `subagent_type` явно назван внешним и
динамическим; критерий строки «Зачем» сведён к «меняет выбор файла/метода/приоритета»; граница haiku/sonnet сведена
к «нужно ли читать и понимать код» со спорными случаями в sonnet по умолчанию.

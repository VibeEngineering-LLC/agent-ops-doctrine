# Приёмка: когда прошивку можно считать продуктом

Решение о выпуске принимается по числам и заполненным строкам, а не по ощущению «вроде
работает». Невыполненный пункт остаётся невыполненным в отчёте — округление в свою пользу
здесь стоит дороже задержки.

## Ворота 1 — наблюдаемость

Проверяется до всего остального: без этого последующие результаты недоказуемы.

| # | Пункт | Как подтверждается |
|---|---|---|
| 1.1 | Зависание задачи приводит к фиксируемому событию, а не к молчанию | искусственное зависание в диагностической сборке даёт ожидаемую реакцию |
| 1.2 | Перезагрузка оставляет посмертный дамп, и его есть куда сохранить | искусственный отказ, дамп прочитан инструментом |
| 1.3 | Все прикладные задачи подписаны на сторожевой таймер | список подписок сверен с картой задач |
| 1.4 | Счётчики потерь, отказов и деградации выводятся наружу | видны в телеметрии, а не только во внутренних переменных |
| 1.5 | Известно, какие данные в дамп не попадут | записано явно, для них предусмотрен отдельный вывод |

## Ворота 2 — ресурсы

| # | Пункт | Критерий |
|---|---|---|
| 2.1 | Запас стека каждой задачи | минимальный остаток за прогон записан; малый остаток объяснён или увеличен |
| 2.2 | Общая свободная память | без монотонного снижения за длительный прогон |
| 2.3 | Наибольший свободный блок | без монотонного снижения; иначе фрагментация |
| 2.4 | Целостность кучи | проверка проходит в конце длительного прогона |
| 2.5 | Дескрипторы, сокеты, задачи | число не растёт от цикла к циклу |

Пункты 2.2 и 2.3 обязательно оба: они ловят разные дефекты и по отдельности пропускают
половину случаев.

## Ворота 3 — время и отзывчивость

| # | Пункт | Критерий |
|---|---|---|
| 3.1 | Все таймауты сопоставлены с физическим временем ожидаемых операций | расхождений на порядок нет; каждое оставшееся объяснено |
| 3.2 | Задержки внешних интерфейсов измерены в перцентилях | не только среднее: хвост распределения и есть предмет жалоб |
| 3.3 | Пропуски срабатывания таймеров | нулевые либо объяснены |
| 3.4 | Загрузка ядер под совмещённой нагрузкой | ни одно ядро не в постоянном насыщении |
| 3.5 | Отзывчивость интерфейса под нагрузкой | без замираний, подтверждено трассировкой, а не «на глаз» |

## Ворота 4 — устойчивость

| # | Пункт | Критерий |
|---|---|---|
| 4.1 | Длительный прогон со всеми подсистемами одновременно | заданная длительность выдержана, условия записаны |
| 4.2 | Сторожевой таймер за прогон | ни одного срабатывания |
| 4.3 | Многократные отключения и переподключения периферии | восстановление каждый раз, без ручного вмешательства |
| 4.4 | Многократные разрывы связи | восстановление каждый раз; настройки, влияющие на задержки, переживают переподключение |
| 4.5 | Снятие питания на активной записи | файловая система цела, состояние согласовано |
| 4.6 | Мусор на входах разборщиков | не приводит к отказу; подтверждено фаззингом |
| 4.7 | Работа при заполненном хранилище | проверена отдельно: это штатный режим для кольцевых схем, а не край |

## Ворота 5 — данные

| # | Пункт | Критерий |
|---|---|---|
| 5.1 | Сквозная сверка независимыми путями | расхождения в пределах документированной погрешности, сама погрешность объяснена |
| 5.2 | Контрольные суммы и порядковые номера | отсутствие порчи и пропусков либо честный учёт потерь |
| 5.3 | Потери учитываются, а не замалчиваются | есть счётчик, он виден снаружи, его показания сходятся с наблюдаемым |
| 5.4 | Поведение при несинхронизированном времени | проверено отдельно: холодный старт до синхронизации часов |

## Ворота 6 — выпускаемая сборка

| # | Пункт | Критерий |
|---|---|---|
| 6.1 | Измерялась именно релизная сборка | диагностические ключи, меняющие тайминги, отключены; замеры повторены |
| 6.2 | Диагностические возможности не уехали в выпуск | сверено по конфигурации |
| 6.3 | Известные дефекты записаны | с уровнем серьёзности и обходными путями |
| 6.4 | Путь отката существует | предыдущая версия доступна и проверена на установку |
| 6.5 | Записано, что НЕ проверялось | честный список пробелов; он полезнее умолчания |

## Форма отчёта

```markdown
# Отчёт об испытаниях стабильности <объект> <версия>

## Итог
Одна фраза: годна к выпуску / годна с оговорками / не годна. Далее — основание.

## Условия
Версия сборки, длительность, что было нагружено, чем измерялось.

## Результаты по воротам
Таблица: ворота, пункт, значение, вывод. Невыполненное — так и написано.

## Находки
Каждая: [Ф] доказательство файл:строка или число замера, уровень серьёзности,
воспроизведение, предлагаемое действие.

## Гипотезы, оставшиеся непроверенными
Каждая помечена [Г], с указанием, каким замером проверяется.

## Что не проверялось
Прямым списком, без смягчений.
```

## Правило формулировок

| Не писать | Писать |
|---|---|
| «Проблема устранена» | «За 72 часа в указанных условиях не воспроизводилась» |
| «Работает стабильно» | «Сторожевой таймер не срабатывал, свободная память не снижалась» |
| «Скорее всего, из-за X» | «[Г] Предположительно X; проверяется замером Y» |
| «Тесты прошли» | «Пункты 2.1–2.5 выполнены, 4.5 не проверялся» |

Разница не стилистическая. Первая колонка закрывает вопрос, вторая оставляет его открытым
ровно настолько, насколько он открыт на самом деле.

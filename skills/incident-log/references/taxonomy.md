# Таксономия подклассов инцидентов

Подкласс ставится в поле «Класс / подкласс». Нужен не для красоты: одинаковые подклассы,
повторяющиеся в журнале, показывают системную причину, которую видно только в накоплении.
Список открытый — новый подкласс добавлять сюда при первом появлении.

---

## РАБОЧИЕ (`W-NNN`) — сбои собственной работы агента

| Подкласс | Что это | Типичная мера |
|---|---|---|
| **silent-fail** | Успешный exit-код / отсутствие ошибки при нулевом или неверном результате | Проверка результата ФАКТОМ (чтение файла/вывода), не по коду возврата |
| **false-green** | Отчёт о ЗАПУСКЕ выдан за отчёт о РЕЗУЛЬТАТЕ (свой или субагента) | Terminal-факт обязателен; запрет вложенного фона в брифах |
| **непроверенное утверждение** | Заявлено число/состояние/«готово» без стерильной проверки | §31.A: стерильный проход, не свой контекст |
| **расхождение заявленного и фактического** | Отчитался N, по факту M (своё или чужое) | Пересчёт независимой командой; «помню» ≠ «прочитал» |
| **нарушение лестницы делегирования** | Машинерия поднята на дорогую ступень (субагент вместо скрипта) | §31.B; три вопроса перед подъёмом |
| **нарушение §-правила** | Известное правило доктрины сорвано (язык, кодировка, границы зон, приватность) | Механическое подкрепление (хук), если детектируется |
| **выход за границу зоны** | Работа в чужой зоне §12 вместо промпта владельцу | Промпт владельцу; read-only тоже не своё |
| **потеря контекста/состояния** | Работа переделана из-за несохранённого состояния | SESSION-STATE, задачи, снапшоты |
| **процессный срыв** | Переключение с текущего замечания, потеря номера, брошенная линия | §25: нумерация и учёт |
| **инфраструктурный** | Краш Ollama, OOM, потеря watcher, CI red, сеть | §4: отчёт супервайзеру + технический hardening |

## ПРОЕКТНЫЕ (`P-NNN`) — дефекты продукта

| Подкласс | Что это | Типичная мера |
|---|---|---|
| **тихо неверный результат** | Работает, не падает, выдаёт неверное число | Регресс-тест на эталонном входе; сверка с первоисточником |
| **краш / исключение** | Падает с ошибкой | Фикс + тест на воспроизводящем входе |
| **регрессия** | Работало, сломалось после правки | Тест, закрывающий именно этот путь |
| **кодировка / локаль** | Mojibake, UnicodeError, битые пути | §2: UTF-8 симметрично на вход и выход |
| **краевой случай** | Пустой вход, один элемент, нули, отрицательные, переполнение | Тест на границах |
| **конфигурация** | Протухший путь, неверный параметр, рассинхрон версий | Валидация конфига при старте |
| **интеграция** | Сломан контракт между компонентами (формат, протокол, API) | Проверка контракта; версионирование |
| **данные** | Испорченный/неполный источник принят за валидный | Валидация входа; провенанс полей |
| **производительность** | Работает, но неприемлемо медленно/жрёт ресурс | Профиль + порог в тесте |
| **дефект генерации** | Баг в коде, сгенерированном моделью и принятом без вычитки | Вычитка обязательна; правки вносить в спеку, не в вывод |

## Как подкласс превращается в системный вывод

Три и более записи одного подкласса в журнале — мера была слишком слабой. Действие:
подняться на ступень выше по лестнице мер (`SKILL.md` → «Лестница мер»), а не добавлять
четвёртую однотипную запись.

Примеры реальных накоплений:
- 3 из 5 записей реестра Цензора оказались **false-green** → системный вывод: «completion
  декларируется только на terminal-факте», перенесён во все брифы субагентов.
- **дефект генерации** ×6 подряд на коде из Ollama (`compact-guard`, 2026-08-15) → вывод:
  вычитка сгенерированного кода обязательна, «сгенерировано» ≠ «проверено».

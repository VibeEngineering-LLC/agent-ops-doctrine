# Скилл: написание научных и научно-популярных статей

**Статус:** production · **Версия:** 2.0.0 · **Обновлён:** 2026-07-28 ·
**Область:** обязателен всем агентам (мандат — `CLAUDE.global.md` в корне репозитория)

Свод правил, накопленных в линии #RN4 (v5→v9.2, июль 2026): ~40 правок оператора,
отзыв внешнего рецензента (8.5–9/10), два редакторских аудита. Проверен практикой,
поэтому вынесен из доменного контура в общий обязательный слой.

## Что применимо где

Скилл вырос из контура «Радоновый риск», и часть его — доменная. Читать так:

| Разделы | Применимость |
|---|---|
| **§12** — каркас статьи (регистр, штампы, добросовестность, структура, реферат) | **Любой текст, любой агент.** Это база |
| **§3** тон и категоричность, **§10** ГОСТ/ВАК, **§11** экспорт в docx | Любой текст |
| **§1** терминология, **§2** методические принципы, **§4** структура RN-отчёта, **§5** EN-зеркало, **§9** калькуляторы | Контур RN и близкие дозиметрические темы; для другой темы — **образец подхода**, а не буквальный словарь |
| **§6** вёрстка (960 px, 17 px, Georgia), **§8** процедура публикации | Веб-артефакты контура; в чужом проекте — его собственные конвенции |
| **§7** словарь спектрометрии | Только спектрометрия/детекторы |

Если задача вне дозиметрии — §12 обязателен целиком, §1/§2 читать как пример того,
насколько плотно надо нормировать термины в своей области, а не переносить дословно.

**Смежное:** внешние факты, числа и ссылки в тексте — через скилл `sci-search`
(запрет выдумки там же, citation-green); аудит готового текста — `fact-audit`.

## 1. Терминология (обязательная)

| НЕЛЬЗЯ | ПРАВИЛЬНО |
|---|---|
| «поле» (о дозовой величине), «истинное поле» | **«приращение Ḣ*(10)»** (расчётная величина); «поле» допустимо ТОЛЬКО как радиационное: «гамма-поле», «поле излучения» |
| «в точке детектора» | **«в точке детектирования»** (EN: at the detection point) |
| «полоса» (о неопределённости) | **«интервал»**; развёрнуто при первом употреблении: «интервал суммарной неопределённости (статистический ДИ, расширенный инструментальной погрешностью)» (EN: total(-uncertainty) interval, НЕ band) |
| «наклон» (о регрессии) | «регрессия МЭД по ОА», «коэффициент связи» |
| «подпись» (= сигнатура) | «признак»; EN «signature» допустим |
| «Мотивация работы» | **«Цель работы»** (EN: The aim of this work) |
| «межсуточный контраст», «внутрисуточные оценки» | «сравнение двух стабильных плато», «оценки по переходным данным отдельных суток» |
| «выход модели» (RU) | «вычисляется моделью»; EN «model output» допустим |
| «recoil-ресуспензия» | «фактор отскока R»; EN «recoil resuspension» допустим |
| «стационар» (существительное) | «установившийся режим»; прилагательные («стационарный баланс») допустимы |
| «прокси» («стекло-прокси») | описательно: «данные стекла — ближайшего гладкого непористого материала» |
| «брекетирующий» | «граничные сценарии (нижняя граница)»; EN «lower-bounding» |
| «пофасадный» | «фактор G отдельных граней» |
| «нормативный уровень» (о ПДК) | «верхний нормативный ориентир (ПДК — предельно допустимая, не типичная концентрация)»; EN regulatory, не normative |
| «по порядку величины» (при факторе <2) | «согласуются в пределах фактора N» — честная количественная формулировка |
| «двумя независимыми методами» (при общих входах) | «двумя независимыми реализациями» |
| Jacobi (в RU-тексте) | «модель Якоби» (ссылки на Jacobi W. — латиницей) |

Разговорные слова под запретом: «выедает» (→ снижает объёмную активность /
обедняет), «сама содержит» (→ позволяет определить), «почти прозрачен» (→ слабо
ослабляет), «в упор», «в разы» (→ в несколько раз), «драйвер» (→ общий фактор),
«робастен» (→ устойчив), «немеряный» (→ неизмеренный), «ломает» (→ нарушает
работу), «лечится» (→ устраняется), «перекачивает» (→ перераспределяет),
«не найдя» (→ в отсутствие), «поле плоское» (→ распределение однородно),
«производящий член», «выедает», «школярские» вводки.

## 2. Ключевые методологические принципы

- **Коэффициент замера один на эксперимент** — измеряется между двумя стабильными
  плато (например, вентиляция вкл/выкл), где ДПР в равновесии с ОА. Регрессии по
  переходным данным — вспомогательные оценки, коэффициентом НЕ являются, как
  «второй интервал» в статью не вводятся.
- **Сравнивать одноимённые величины в одних единицах**: вычисленное приращение
  Ḣ*(10) (и вычисленное ПОКАЗАНИЕ прибора = приращение + корпус + отклик) против
  измеренного приращения. С замером сравнивается именно показание.
- **Расхождение** формулировать: «измеренное превышает вычисленное в N раза»,
  «лежит вне пределов погрешности замера» — не «ниже края», не «×N к центру».
- Инструментальную погрешность прибора относить к ЗАМЕРУ (суммарный интервал),
  не к модели.
- Входные величины по возможности ВОССТАНАВЛИВАТЬ из данных самого эксперимента.
- Чувствительности пересчитывать на актуальной механике модели (урок: «подставка
  −15 %» старой версии оказалась −1…−2 % на полной модели).
- Отношения: в прозе «в 1.43–1.45 раза», в таблицах «×1.43–1.45». Не выбирать
  благоприятный край диапазона.

## 3. Тон и категоричность

Снижать категоричность выводов: вместо «исключён / кандидатом не является /
не может / не даёт / невозможно» → «не объясняет наблюдаемое расхождение»,
«вклад в рамках настоящей модели несущественен», «сценарий не согласуется с
данными», «по замеру не проявляется». Заголовки разделов — академичные:
«Анализ альтернативных механизмов», «Возможные источники остаточного
расхождения» (не «Проверенные и исключённые», не «Кандидаты»).

НЕ выхолащивать (сильные стороны по рецензенту): физическая интерпретация сразу
после каждой формулы; мотивировки «зачем вводится элемент модели»; отсутствие
канцелярита. Не писать «слишком для студентов»: без развёрнутых вводок «мы
проверили А, затем Б», план статьи — одной сухой фразой.

## 4. Структура статьи

Реферат из четырёх абзацев: «Цель / Приборы (и помещение) / Методы / Вывод» —
номинальные конструкции, точки с запятой; «Вывод» в одном регистре с «Методами».
В «Выводе» — прямые формулировки без оговорок «не X, а Y». Разделы: Введение →
Исходные данные → Методы → Результаты → (Численная верификация) → Сравнение с
экспериментом → Ограничения → Выводы → Заявление об использовании ИИ → Литература.
Раскрывать аббревиатуры при первом употреблении (МЭД, ДИ, X — в подписях таблиц
тоже). История версий — только в CHANGELOG, публичная статья без неё.

**Заявление об использовании ИИ** — обязательный раздел: агенты/модели/роли
(аналитика, верификация, аудит), роль оператора (постановка, измерения, входы,
приёмка, ответственность), внешнего специалиста; плюс строка в шапке под lede.

## 5. EN-зеркало

RU и EN контейнеры правятся СИНХРОННО. Стандартные EN-термины сохраняются
(bracketing→lower-bounding, recoil resuspension, model output, slope, signature).
Кальки под запретом: the analytics→the analytical model; normative→regulatory;
passport→(manufacturer's) datasheet; contour(нариц.)→pipeline; self-decay→
radioactive decay; chain link→chain member; folding→convolution; field
measurement→in-situ measurement; band→interval; «where X — Y»→«where X is Y»;
×2.1→a factor of 2.1; 5·10⁷→5×10⁷; BrE единообразно (normalised, per cent).

## 6. Вёрстка и артефакты

Колонка 960px, шрифт 17px («Georgia»); figure/figcaption со сквозной нумерацией
Рис. N; таблицы со сквозной нумерацией и расшифровкой переменных в подписи;
рисунки — файлами в figures/ эксперимента (той же версией, что показаны в чате).

**Подписи на рисунках — на языке версии.** Отговорка «(Figure labels are in
Russian.)» в EN-версии больше не применяется: скрипт рисунка получает флаг языка
(`EN = bool(os.getenv("FIG_EN"))`), пишет `*_en.png` рядом с русским файлом, EN-версия
статьи ссылается на `_en`. Один скрипт — два выхода, тексты внутри скрипта тернарниками
(`"depth, µm" if EN else "глубина, мкм"`), чтобы версии не разъезжались.

Аннотации точек не должны налезать на оси: крайним точкам задавать индивидуальные
смещения и выравнивание (`ha`/`va`), а не общий `xytext`; добавлять запас по осям
(`set_xlim`/`set_ylim`) — «уместится само» не работает для последней точки справа.

Если РУ-версия показывает английский рисунок — сперва сверить размеры файлов
`X.png` / `X_en.png` и перегенерировать: чаще это кэш браузера (Ctrl+F5), а не
перепутанные ссылки.

## 7. Терминология спектрометрии (нормировочный словарь)

Для терминов детектора/спектра (эффективность, отклик, пик, разрешение,
пределы обнаружения) — сверяться с конспект-словарём
`references/terminology-budyka-2021.md` (по: Будыка А.К. «Спектрометрия
ионизирующих излучений. Основные понятия и терминология», НИЯУ МИФИ, 2021).
Ключевые нормы оттуда:

- «пик полного поглощения (ППП)» ≠ «фотопик» — ППП формируют три механизма
  (фотоэффект + многократный Комптон с полным поглощением + пары), фотопик —
  только фотоэффектная часть;
- «функция отклика детектора» / «свёртка отклика» — канонические термины
  (не «функция чувствительности»);
- эффективность всегда с уточнением вида: абсолютная / по ППП / внутренняя
  (собственная) / геометрическая / относительная — разные величины, не
  взаимозаменяемы;
- «полуширина (ПШПВ)» = FWHM — ПОЛНАЯ ширина на половине высоты;
- «чувствительная область детектора» (в Geant4-контексте допустим вариант
  «чувствительный объём» = sensitive volume);
- словарь охватывает только спектрометрию, НЕ дозиметрию — термины МЭД,
  H*(10), дозовые коэффициенты по-прежнему нормируются через
  `references/radon-normy.md`.

## 8. Процедура правки и публикации (#RN-отчёты)

1. Источник истины — RN4_report.html (RU+EN контейнеры); md ТОЛЬКО регенерацией
   конвертером (scratchpad/html2md_v8.py или его наследник в scripts/).
2. Правки — скриптом с assert-контролем каждого образца (атомарно: промах — файл
   не записывается).
3. Число-контроль при редакторских правках: мультимножество числовых токенов
   до/после — значения результата меняться не должны.
4. Секрет-скан (токены, e-mail, локальные пути, имя пользователя).
5. Копия в publish/, gh api PUT с контролем sha, live-проверка curl-циклом
   (CDN до 3–4 мин), карточка корневого index.html — синхронно.
6. CHANGELOG + SESSION-STATE после каждого пуша. Публикация — только по явной
   команде оператора.
7. Замечания оператора копить в REMARKS-файле и применять пакетом по команде
   («собирай и жди» → «делай»); перед публикацией — независимый аудит
   (actor≠verifier), предписания исполнять до пуша.

## 9. Интерактивные приложения к статье (калькуляторы, 3D)

Уроки линии «урановый бисер» (июль 2026): к статье приложен калькулятор
Ḣ<sub>p</sub>(0,07) с 3D-визуализацией поля.

**Модель, а не интерполяция.** Калькулятор не должен «растягивать» три
опубликованных числа. Строится суррогатная модель с физической структурой —
для контактной дозиметрии это точечное поверхностное ядро h(r), свёрнутое с
профилем эмиссии источника, с суммированием по элементам и усреднением по
нормативной площади. Тогда геометрия и размер источника входят как параметры
интегрирования, а не как подгонка, и экстраполяция осмысленна. Проверка
самосогласованности обязательна: плотная укладка любого размера зерна обязана
давать предел сплошного слоя; мелкое зерно — падать по фактору насыщения
1 − exp(−ν·ρ·h). Не сошлось — модель неверна, а не «приблизительна».

**Подгонка ядра.** Калибровать по ВСЕМ доступным точкам МК, включая кривую
усреднения по площади (hot-particle) — именно она фиксирует форму вблизи оси;
без неё ошибка на малых площадях достигает ±10 %. Матрицы расстояний от
параметров не зависят — считать их один раз (гистограммы по кольцам источника),
иначе МНК идёт часами вместо секунд. Целевая невязка — доли процента (достигнуто
0,68 % на 7 точках); если форма не ложится, добавлять физический параметр
(радиальный профиль эмиссии), а не свободные множители.

**Доверие к странице.** На самой странице — таблица «модель против МК»,
считаемая на лету тем же кодом, что и результат; дисклеймер об ответственности;
раздел границ применимости; автоматические предупреждения при выходе за область
калибровки (диаметр, содержание, плотность). Числа не публиковать без ± и без
указания, что именно входит в неопределённость.

**Двуязычность и числа.** Переключатель РУС/ENG как в статье; десятичная
запятая в RU и точка в EN (ГОСТ 8.417) — включая динамические строки, оси
графиков и таблицы; единицы переводить (мкЗв/ч ↔ µSv/h, кБк ↔ kBq, % масс. ↔ wt %);
в RU — склонение при числительном («1 бусина / 2 бусины / 11 бусин»). Хранить
язык в localStorage, по умолчанию RU.

**Кэш ES-модулей (реальный инцидент).** Браузер может подставить закэшированный
`app.js` к обновлённому `index.html` — разметка новая, обработчики не навешаны,
кнопка «не работает». Ставить метку версии на КАЖДЫЙ модуль, включая
внутренние импорты: `src="./app.js?v=2"`, `import ... from './physics.js?v=2'`.
Внешние библиотеки вендорить в репозиторий (three.js), не тянуть с CDN.

**3D-визуализация поля.**
- Рельеф величины направлять ВНИЗ, «в ткань»: иначе поверхность поля перекрывает
  сами объекты. Это ещё и физически честно — доза набирается под источником.
- Высоту рельефа задавать в абсолютных мм, а не долей размера сцены, иначе на
  крупных раскладках объекты тонут.
- Форма объекта должна быть узнаваемой: сплюснутая сфера читается как «таблетка»;
  бисер-рокайль — тор со сквозным отверстием. Стекло = `MeshPhysicalMaterial`
  + `clearcoat` + процедурная envMap (без карты окружения материал выглядит
  пластиковым).
- Орбита: тянем вниз — камера поднимается (как в общепринятых контролах);
  разрешать отрицательный угол места, чтобы поле можно было осмотреть снизу,
  и скрывать подложку при взгляде снизу.

**Отладка WebGL без скриншотов.** Когда панель браузера не композитит кадры,
снимать рендер программно: `renderer.render()` → `canvas.toDataURL()` → POST на
локальный питон-приёмник, пишущий PNG на диск, и читать файл. Заодно
`renderer.info.render.triangles` и `gl.readPixels` подтверждают, что сцена не пуста.

## 10. ГОСТ / ВАК-оформление (нормативный референс)

При подготовке статьи/отчёта к **печатной публикации или подаче в рецензируемый
журнал** (в т.ч. перечня ВАК) — сверяться со сводом
`references/gost-vak-oformlenie.md`: применимые стандарты (7.5-98, 7.32-2017,
Р 7.0.5-2008, Р 7.0.100-2018, 8.417-2002), обязательные элементы (УДК, аннотация
200–250 слов, ключевые слова 3–15, IMRAD, References), единицы и числа
(десятичная запятая в RU, пробел число↔единица, СИ), подписи таблиц/рисунков
(«Таблица N —» сверху, «Рисунок N —» снизу), библиографические ссылки
(затекстовые `[N]` / `[N, с. X]`). Приоритет — «Правила для авторов» конкретного
журнала. Веб-артефакты следуют house-CSS (§6); §10 включается на печатной ветке.

## 11. Экспорт HTML-страниц в Word (docx) для правки автором

На ноутбуке нет ни `pandoc`, ни LibreOffice (`soffice.py` скилла `docx` падает —
рассчитан на Unix, использует `AF_UNIX`), поэтому штатный workflow скилла `docx`
не работает напрямую. Вместо него — `scripts/html_to_docx.py` (python-docx +
BeautifulSoup, ставятся через `pip install python-docx beautifulsoup4`).

Разбирает страницу СТАТИЧЕСКИ (без выполнения JS), воспроизводя ту же логику,
что и `applyLang()`/CSS в браузере: словари `var I18N={ru:{},en:{}}` и
необязательный оверлей `var SIMPLE={...}` (для «простой версии» статьи),
`data-i18n`-подстановку, правила видимости `body.simple СЕЛЕКТОР{display:...}`.
Рассчитан на структуру calculator-страниц контура (`header`/`section[aria-label]`/
`footer`); для страницы другой структуры — не универсален, потребует правки.

```bash
python C:\Users\<you>\claude-skills\rn-article-style\scripts\html_to_docx.py \
    index.html --mode sci --lang ru -o out_sci.docx --source-url "https://.../"
```

Особенности: цитаты (`blockquote.quote`) — курсивом с отступом и подписью
источника; калькулятор — таблицей полей «значение по умолчанию — пояснение»
(результат `calc()` не воспроизводится — это не статический контент);
inline-SVG схема — текстовым списком подписей узлов (не картинка); `<table>`
конвертируется как есть. Проверка результата — конвертацией в PDF через
COM-автоматизацию MS Word (`Word.Application`, `doc.SaveAs2(pdf, 17)` из
PowerShell; экспорт может занимать &gt;60&nbsp;с — использовать фоновый режим),
затем рендер страниц PDF в PNG через `pymupdf` (`pip install pymupdf`) для
визуальной сверки — на ноутбуке нет `pdftoppm`.

## 12. Каркас научно-популярной/научно-технической статьи (ОБЯЗАТЕЛЬНЫЙ)

Базовый каркас для ЛЮБОЙ статьи контура с нуля (не только RN-отчётов с
численной верификацией — для них специфика в §4 остаётся сверху этого каркаса).
Цель: текст читается как глава диссертации/монографии для инженерно-технической
аудитории, а не как журналистский материал — при полной доступности без
профильного образования. Упрощение, искажающее научный смысл, запрещено.

**Приоритет требований при конфликте:** достоверность > логика изложения >
ясность объяснения > практическая ценность. Первое никогда не приносится в
жертву третьему.

### 12.1. Запрещённый регистр

Помимо разговорных слов и калек (§1) — под запретом как класс: риторические
вопросы, обращения к читателю («вы могли заметить»), рекламные обороты,
художественные сравнения, сенсационные формулировки, категоричные заявления
без доказательства (ужесточает и без того обязательное §3).

**Штампы (запрещены дословно):** «как известно», «следует отметить», «важно
понимать», «интересно отметить», «на сегодняшний день», «не секрет, что»,
«учёные считают», «можно сказать», «очевидно», «безусловно», «нельзя не
отметить». Каждое предложение обязано нести новую информацию — не пересказывать
предыдущее другими словами.

**Аналогии — не замена термину, а объяснение рядом с ним.** Разговорный аналог
вместо строгого понятия запрещён («поле» вместо приращения Ḣ*(10) — см. §1).
Но физическая интерпретация и мотивировка «зачем вводится элемент модели»
сразу после формулы — сильная сторона стиля (§3, подтверждено рецензентом) и
СОХРАНЯЕТСЯ: причинно-следственное объяснение — это не упрощение аналогией, а
раскрытие механизма точным языком.

**Залог.** Русский научный регистр традиционно безличен («показано, что…»,
«рассматривается…») — это НЕ ошибка и ломать против регистра не нужно.
Действительный залог предпочитать только там, где у действия есть явный
субъект и пассив реально усложняет фразу, а не там, где безличность — это
корректная научная форма.

### 12.2. Научная добросовестность (жёсткий запрет)

Не выдумывать результаты, нормативные документы, экспериментальные данные,
ссылки, статистику, численные значения — ни при каких обстоятельствах, даже
для правдоподобия черновика. Если существует несколько научных подходов —
кратко развести различия, не выбирая один как единственно верный без
обоснования. Предположения отделять от доказанных фактов явно (маркерами
«предположительно», «по одной из моделей» — не растворять в тексте наравне с
фактами). Каждый вывод обязан следовать из изложенного материала статьи, а
не апеллировать к внетекстовому авторитету. Эта норма — то же требование, что
`fact-audit` предъявляет к АУДИТУ (citation-green: не путать существование
источника с истинностью приписанного ему числа) — здесь оно действует на
этапе НАПИСАНИЯ, до всякой проверки.

### 12.3. Реферат и ключевые слова

**Реферат** — 150–300 слов, ПЕРЕД основным текстом. Самостоятельный текст: без
ссылок на рисунки/таблицы/литературу/номера разделов (проверяется грепом на
«рис.», «табл.», «[1]», «разд.» — ноль совпадений). Содержит: объект
рассмотрения, актуальность, цель, рассматриваемые процессы/методы, основные
результаты и выводы, область практического применения. Формат абзацев — как
в §4 («Цель / Приборы / Методы / Вывод», номинальные конструкции); граница
150–300 слов добавляется поверх, а не взамен.

Для печатной подачи/ВАК действует иной норматив аннотации (200–250 слов) —
`references/gost-vak-oformlenie.md` (§10), приоритет отдаётся правилам
конкретного журнала.

**Ключевые слова** — 8–15 слов/словосочетаний по умолчанию (для печатной
подачи/ВАК — 3–15 по §10, следовать целевому журналу).

### 12.4. Структура и нумерация

Порядок по умолчанию: Реферат → Ключевые слова → Введение (актуальность,
степень разработанности, постановка проблемы, цель, задачи, область
применения) → Основная часть по разделам → Заключение (результаты, выводы,
практические рекомендации, ограничения, перспективы) → Заявление об
использовании ИИ (обязательно, §4) → Литература (§10). Для RN-отчётов с
расчётной верификацией — конкретная раскладка разделов остаётся по §4
(Исходные данные → Методы → Результаты → Численная верификация → Сравнение с
экспериментом → Ограничения).

**Нумерация разделов.** Короткие веб-статьи (текущий формат house-CSS, §6) —
плоская сквозная нумерация `<span class="num">N</span>` как уже принято во
всех опубликованных статьях; ломать не нужно. Для длинных
монографического объёма материалов (много подтем внутри раздела) — допустима
многоуровневая нумерация `1. → 1.1. → 1.2. → 2. → 2.1.`; выбор формы —
решение автора статьи под конкретный объём, не переключается «на глаз»
посередине текста.

Каждый раздел содержит по существу вопроса: определение явления, описание
процессов (физических/химических/технических), анализ влияющих факторов,
преимущества и ограничения метода (если применимо), практическое значение.
Раздел завершается кратким выводом 1–3 предложения — не пересказ раздела,
а то, что из него следует для дальнейшего изложения. Переход от раздела к
разделу — от общего к частному, от определения к объяснению, от принципа к
применению, от причины к следствию; резкие смены темы без связки запрещены.

### 12.5. Терминология и единицы

Термин — в одном значении по всей статье; при первом употреблении — краткое
определение (см. также словарь §7 для спектрометрии). Единицы — СИ,
обозначения — по действующим ГОСТ/международным стандартам (§10, §12.3
пересекается с §1 по формулировкам — при расхождении приоритет у §1 как более
проверенного практикой).

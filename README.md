# agent-ops-doctrine

Рабочий свод правил эксплуатации Claude Code (или похожего CLI-агента) в долгоживущих
многопроектных сценариях: дисциплина делегирования, гигиена контекста, самоаудит, журналирование
инцидентов, петли для повторяемых машинно-проверяемых задач, плюс библиотека переиспользуемых
скиллов — независимый аудит, оркестрация multi-agent workflow, исследование, документация,
передача состояния между сессиями.

Это не фреймворк и не инструмент — это дистилляция правил, которые пережили реальные инциденты
за месяцы ежедневной многоагентной работы. Специфику (пути, имена моделей, пороги) адаптируйте
под свою среду — сама дисциплина рассчитана на перенос.

## Содержание

- [`DOCTRINE-CORE.md`](DOCTRINE-CORE.md) — 16 базовых принципов на английском (лестница
  делегирования, бюджет контекста, дисциплина самоаудита, журналирование инцидентов,
  систематическая отладка, петли для повторяемых задач). Английский — для международной
  аудитории; сами скиллы ниже в основном на русском (язык оригинала).
- [`LICENSE`](LICENSE) — MIT.
- `skills/` — 22 скилла Claude Code (`SKILL.md` + `references/` + при необходимости `scripts/`).
- [`references/loop-doctrine.md`](references/loop-doctrine.md) — полное тело практики «петель»
  (§16 в `DOCTRINE-CORE.md` — конспект; здесь — гейт входа, три кольца защиты, стерильность
  локальных аудиторов, формат карточки и файла состояния, каталог сбоев). Русский, на русском
  написан и весь остальной корпус ниже.
- [`scripts/audit_doctrine.py`](scripts/audit_doctrine.py) + [`spec_audit_doctrine.md`](scripts/spec_audit_doctrine.md) —
  рабочий инструмент стерильного аудита markdown-документа пятью независимыми линзами через
  локальную модель (Ollama), на который ссылается `loop-doctrine.md`. Запускается сразу из этого
  репозитория (`python scripts/audit_doctrine.py --selftest`), пути к зависимостям резолвятся
  относительно расположения скрипта.

## Перечень скиллов — что зачем

| Скилл | Что делает | Зачем нужен |
|---|---|---|
| `censor` | Методология независимого reviewer-контура: аудит, факт-чек, надзор над другими контурами | Когда один и тот же агент не должен проверять сам себя (actor≠verifier) |
| `six-corner-audit` | Аудит одного финализированного артефакта по факту: 6 углов рассмотрения + отдельный скептик-верификатор | Перед пушем/мерджем — независимая проверка готового результата |
| `fact-audit` | Read-only комплексный аудит кодовой базы с приоритизированной критикой и провенансом file:line | Когда нужно «что не так в коде» по всей базе, не по одному диффу |
| `new-contour` | Bootstrap нового контура/агента: делегирование по умолчанию, гейт на необратимых действиях, отчётность файловым каналом | Онбординг новой долгоживущей роли/сессии |
| `workflow` | Оркестрация multi-agent workflow и делегирование на локальную LLM (Ollama) | Когда бы работу можно параллелить или делегировать дешёвой модели вместо дорогой |
| `self-learning` | Петля самообучения: сбор уроков из отчётов субагентов, триаж по корзинам, каталог классов ошибок | Чтобы найденный урок не терялся и не открывался заново тем же контуром |
| `incident-log` | Два раздельных журнала — рабочие инциденты агента и проектные баги продукта — с лестницей мер | Систематическая фиксация провалов вместо разового «запомню» |
| `session-handoff` | Структура передаточного документа сессии: владелец, дата устаревания, открытые задачи | Продолжение работы после /clear, рестарта или клонирования роли |
| `compact-guard` | Переживание сжатия контекста: снимок состояния до компакта, восстановление после | Чтобы важные факты не терялись при автосжатии диалога |
| `md-doc` | Вёрстка читаемых markdown-документов + HTML-версия для печати | Оформление отчётов/справок для человека, не только для модели |
| `rn-article-style` | Научный регистр публичного текста: без штампов, без выдуманных данных и ссылок | Перед публикацией любого текста наружу |
| `measure-methodology` | Методика измерительного прогона: поверка стенда до объекта, три исхода (объект/среда/стенд) | Чтобы не спутать дефект измерительного инструмента со свойством измеряемого |
| `sci-search` | Верификация внешних фактов по первоисточникам: DOI, стандарты, нормативы | Перед тем как назвать число или ссылку — память модели не источник |
| `deep-research` | Многоисточниковый разбор большого вопроса силами нескольких субагентов параллельно | Когда один агент не покрывает вопрос за разумное время |
| `delegation-manager` | Координатор делегирования задач в GitHub-проекте (issues/PR/статусы) | Управление очередью задач между несколькими исполнителями |
| `dev-env` | Инструменты рабочего окружения: транспорт команд, граф проекта | Настройка окружения под долгую работу с одним и тем же проектом |
| `doc-tools` | Диспетчер работы с документами: чтение/OCR/создание — маршрутизация между специализированными инструментами | Единая точка входа вместо запоминания, какой инструмент за что отвечает |
| `terminology` | Терминологический словарь предметной области (двуязычный) | Единообразие терминов между сессиями и контурами |
| `web-publish` | Стек фронтенд-разработки + метод публикации демо-страниц с гейтами безопасности | Повторяемый, проверенный способ публиковать что-то наружу |
| `firmware-stability` | Прошивка как продукт: зависания, утечки, гонки, приёмочные тесты | Когда результат работы — не просто код, а устройство, которое должно жить сутками |
| `markitdown` | Конвертация произвольного документа в Markdown | Дефолтный способ превратить PDF/docx/pptx в текст для модели |
| `doc-extract` | Примитивы извлечения текста: PDF, сканы (OCR), устаревшие форматы Office | Когда `markitdown` не справляется — сложные сканы и легаси-форматы |

## Чего здесь сознательно нет

Проектные и предметно-специфичные скиллы (прошивки конкретных устройств, личные пайплайны
данных, финансовые калькуляторы, инфраструктура, завязанная на одну машину) — исключены. Это
переносимый операционный слой, а не продукты, построенные поверх него.

## Периодичность обновления

Это периодический (примерно раз в неделю) экспорт из рабочей приватной конфигурации, а не
постоянно синхронизированное зеркало. Возможен небольшой дрейф между тем, что здесь, и
последней внутренней версией.
